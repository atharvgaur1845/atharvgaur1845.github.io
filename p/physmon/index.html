BidBrain

  • PROJECT
  • GRAPH HACKS 2026
×

Overview

A Graph Hacks 2026 project: a construction company's documents in one FalkorDB graph, used by agents to qualify public tenders clause by clause, prove that required documents are missing, settle conflicting documents and cite the page behind every answer. All data is synthetic.

Problem

  • Infrastructure firms win tenders by proving past performance: similar works above a value, qualified personnel, valid bank guarantees, turnover.
  • The proof is spread across hundreds of certificates, letters, CVs, ledgers and statements, and those documents contradict each other over time.
  • The questions span several hops (person → credential → work → client → portfolio) and some ask for what is absent, which a retriever cannot see.

Approach

687 PDFs and 9 spreadsheets are extracted into facts and claims, each claim carrying its source, page, issuer and authority. These load into a FalkorDB graph with a 384-d HNSW vector index and a full-text index over 2,564 chunks. Six agents share one registry of 25 graph tools, also served over MCP. A verifier with no LLM re-checks verdicts, and arithmetic happens in the graph, never in the model.

Map

Decisions

Decision Alternative Why Trade-off
Store contestable values as Claims; Work.value is a view of the winning claim Overwrite values when documents change A corrigendum never destroys history; every decision is traceable More nodes (1,648 claims)
Prove absences from the boundary of the set Vector retrieval A retriever reasons only over what it fetched, so it cannot see a missing letter Requires a complete, connected graph
One tool registry for agents, MCP server and evaluation oracle Separate tool code per consumer The same 25 functions are tested once and used three ways Tools must stay generic
Arithmetic re-reads values from the graph in exact integer rupees Let the LLM add numbers Removes arithmetic errors from the model More tool calls
Per-visitor graph copies (GRAPH.COPY), reaped after 24 h One shared graph One visitor resolving a conflict never changes what the next sees Storage per session

Evidence

Claim Value Source
Tool sufficiency 354 / 354 (21 / 21 on true gold) README evaluation
Conflict engine, JSON stream P = R = F1 = 1.00 on 275 events README (rules and labels written by the same team)
Conflict engine, PDF path F1 1.00 after fixing 2 bugs; first run 0.976 README
Q&A accuracy vs vector RAG not reported; benchmark still running README

Limits

  • The corpus is fully synthetic (BITS Hackathon dataset); no real company or person.
  • The JSON-path conflict scores mostly check consistency, since the same team wrote the rules and the labels.
  • The demo LLM (Qwen3-32B) is hosted via Groq/Cerebras; evaluation runs on vLLM.
  • The extraction layer was co-written with Shoyam Mishra for an earlier BITS hackathon; the graph model, agents, conflict engine, MCP, evaluation and UI were built for Graph Hacks.

CUHK-X Challenge, Small Model Track

  • COMPETITION
  • UBICOMP/ISWC 2026

Overview

A 40-class activity recognition system for the CUHK-X Challenge Small Model Track, built from five sensor specialists and a sequence decoder, shipped as one file of 96.37 MB. It finished 14th of 326 teams on the private leaderboard and was selected for a poster at the CUHK-X Challenge Grand Finals, UbiComp/ISWC 2026, Shanghai.

Problem

  • Recognise 40 everyday activities from privacy-preserving sensors: infrared, depth, thermal, skeleton, five wearable IMUs and radar.
  • Training data: 2,933 clips from 18 people. Test: 405 clips from four people never seen in training.
  • Every parameter used at inference, detectors included, must fit in one file of at most 100 MB.
  • The top 15 move to a Selection Stage where organizers reproduce the result from the package.

Approach

Five specialists each read the signal they are best placed to read: a person crop and a wrist crop from infrared plus depth, the full thermal frame, a 20-member skeleton and IMU stack, and a tree model on IMU statistics. Their log-probabilities are combined after reconciling the class priors each one was trained with. A decoder then uses the order in which each person recorded the activities to correct labels that do not fit the sequence.

Map

Decisions

Decision Alternative Why Trade-off
Resolution per view: 384 px for the person crop, 224 px for wrist and thermal One resolution for all views Measured: 224 → 288 → 384 px helped the person view (pooled OOF 0.714 → 0.730 → 0.733) but cost the wrist view 1.36 points Three resolutions to manage
Fuse in log space after dividing the plain-CE stack by the training prior Average probabilities directly Members trained with different losses emit posteriors under different priors; fusing in the wrong direction measured 0.587 against 0.627 Fusion depends on knowing how each member was trained
Ordered transition decoder over each subject's clips Per-clip argmax Subjects record activities in a scripted order; measured +10.4 pooled OOF and +3 to +5 public clips Couples predictions within a sequence
int5 bit-packed video weights, int8 skeleton stack, fp16 detectors Uniform int8 Needed to fit 96.37 MB; int8 detectors moved 150 of 405 crop windows, so detectors stay fp16 int5 cost one public clip, recovered by the thermal weight soup
Ship the 405 test crop windows inside the package Recompute windows at inference Recomputing on another GPU matched only 184 of 405 person windows and moved 22 predictions Unseen clips still use the packaged detectors live

The Floor Moves With the Probe

  • RESEARCH
  • ACCEPTED, REO @ NEURIPS 2026
×
overviewproblemapproachmapdecisionsevidencelimitslinks

Overview

A workshop paper accepted to the 2nd Workshop on Advances in Representation Learning for Earth Observation (REO) at NeurIPS 2026. It adds two trivial baselines to a comparison of self-supervised objectives on satellite imagery and shows that the baseline, and the margin over it, both move with the capacity of the probe used to evaluate them.

Problem

  • Self-supervised objectives for satellite imagery are usually compared with each other, almost never with a trivial floor.
  • Without a floor, a method can look useful while encoding little that the raw input does not already carry.
  • The question: how much do these objectives add over a baseline with no parameters, and does the answer depend on how they are read out?

Approach

Five objectives (temporal JEPA, spatial JEPA, MAE, BYOL, SimCLR) pretrain the same encoder on PASTIS Sentinel-2 series for 100 epochs. Two floors are added: patch-mean raw spectral bands (zero parameters, 10 channels) and the same architecture with random weights. Encoders are frozen and read by probe heads whose spatial receptive field is swept over 1, 3, 5 and 9. Epochs, per-step batch, effective batch and probe budget are matched; compute is not.

Map

Decisions

Decision Alternative Why Trade-off
Add a zero-parameter raw-band floor and a random-init floor Compare objectives only with each other A floor shows what an encoder adds over its input Two more cells per probe
Sweep probe receptive field 1, 3, 5, 9 Report one probe The floor rose 4.76 → 21.45 mIoU across the sweep, so one probe hides the dependence Fixed 15-epoch probe budget: capacity and ease of optimisation are not separated
Report margins in units of across-seed sd, n = 3 p-values At n = 3 no rank test is informative Wide uncertainty bands
Pre-register the decision rule before running the floors Decide after seeing results Fixes the claim in advance The rule itself fixed one probe capacity, the choice the paper is about
Match per-step batch, not only effective batch Match effective batch only SimCLR negatives and the variance-covariance term are computed per micro-batch Compute differs: 6.24 vs 0.55 GPU-hours per seed (temporal JEPA vs MAE)

Evidence

Claim Value Source
Raw-band floor across RF 1 → 9 4.76 → 21.45 mIoU Paper
Temporal JEPA margin over the floor +10.56, +4.78, −0.15, −1.57 (RF 1, 3, 5, 9; n = 3) Paper
At RF 3 19.26 ± 1.30 vs floor 14.47 ± 0.01 Paper, Table 1
Shuffled-time control keeps about 70% of the conv margin (seed 0) Paper, Appendix
Without the anti-collapse penalty effective rank 312.4 → 1.49 of 512; conv mIoU 20.03 → 8.68 (seed 0) Paper, Appendix
Status Accepted, camera-ready forthcoming Atharv

Limits

  • n = 3 seeds (SimCLR and BYOL n = 2); the collapse ablation and shuffled-time control are single-seed.
  • Frozen probes on one dataset, series truncated to 32 acquisitions, no fine-tuning.
  • No reversal is claimed at RF 9: the margin there is 1.2 sd.

FlashLOB

  • IN PROGRESS

Overview

A research project in progress: a systematic study of context length for limit-order-book transformers, a Hawkes-calibrated attention bias, and a Triton sparse-attention kernel to make long contexts trainable. Code and unit tests are complete; real-data experiments have not run yet, so there are no results.

Problem

  • Does long order-book history carry more predictive signal for volatility than the short windows usually used?
  • If so, is that signal concentrated on high-impact events that Hawkes microstructure theory can predict?
  • Dense attention memory grows quadratically with context, which limits how long a history fits on a GPU.

Approach

Order-book messages become event tokens with a time-aware rotary embedding. Attention scores get a bias from a fitted multivariate exponential Hawkes process per event-type pair, and a Triton kernel computes only a structured sparse set of blocks. The work runs as gated phases, each with a pass condition before the next starts.

Map

Plan and gates

Phase What Gate
−1 Pilot Dense transformer, context 100 to 2048, 1 stock, 1 seed, 5 epochs No-go pivots to an empirical-only study
0 Context sweep Context 100 to 4096 × 3 seeds Volatility MAE improves ≥ 3% from 500 to 2048
1 Hawkes ablation Dense, sliding, volatility-threshold, Hawkes bias Hawkes ≥ volatility-threshold by ≥ 0.5% accuracy
2 Kernel Triton FlashLOB kernel, correctness then VRAM and throughput Matches the reference at FP16 tolerance
Baselines DeepLOB, TLOB, dense transformer, FlashLOB under one protocol n/a

Status

Code built and unit-tested; real-data runs pending. Nothing here is a finding yet.

Limits

  • No experimental results.

Links

  • Repository: https://github.com/atharvgaur1845/FlashLOB

Overview

Team Short Circuits from BITS Pilani reached the finals of the LAM Research Challenge 2025, as one of 24 finalists from about 8,000 registrations. The team built an arena system in simulation, then on real hardware, then adapted it to surprise tasks in the finals.

Problem

  • Round 1: build the whole arena in CoppeliaSim, including line following, gate-based IR detection and conditional actuation of a pump and an LED display.
  • Round 2: build it physically from Lam Research and T-Works kits and make it work under real alignment, latency, sensing noise and power constraints.
  • Finals: add surprise elements under tight timelines.

Approach

Every action is triggered by a sensor event. IR line sensors steer a mecanum base; an IR gate event actuates a peristaltic pump and displays; ultrasonic sensing halts the robot before obstacles. The same gate logic later drove the finals' surprise elements.

Map

What was built

  • 4-axis robotic arm with gripper
  • 4-wheel mecanum drive base
  • Line follower with IR sensors
  • Ultrasonic obstacle detection and halt logic
  • Peristaltic pump control and actuation
  • Gate-triggered logic integrated with displays and peripherals
  • Finals: dual liquid cooling and transportation systems controlled via gate sensors; hologram control through gate logic

Overview

A 2D roguelite arena that infers how the player is playing and reshapes physics, visuals and music from that inferred state, with no scripted difficulty levels. It runs in the browser, and a hierarchical reinforcement-learning agent can play it in any of the five play styles on command. Ideated with Shoyam Mishra; the RL agent is Atharv's.

Problem

  • Games usually adapt through fixed difficulty levels or scripted modes.
  • The goal: infer the player's current state continuously from how they move and act, and let that state drive the world directly.

Approach

Five features per frame (speed, keypress rate, heading variance, threat, idle time) feed a non-causal attention model over a 32-frame window: 16 past frames and 16 frames projected by the game's physics. It outputs π, a mixture over five archetypes (arousal, tactical, overload, flow, apathy). A matrix maps π to physics (E = M · π), a small network maps it to shader latents, and π crossfades five musical identities.

Map

Hand-tuned M for π → physics Learned mapping Predictable, designable behaviour Manual tuning
Music scale switches only after an archetype holds ~1.2 s Switch instantly Otherwise the melody rewrites itself several times a second Slight lag
Browser build uses weights dumped from PyTorch Reimplement and retrain Same π as the desktop game Weights must be re-exported on change

Neural Debris Removal

  • PROJECT
  • COMPETITION
×
overviewproblemapproachmapdecisionslimitslinks

Overview

A competition entry for Neural Debris Removal in Streak Detection Models. A satellite-streak detector was trained on poisoned data. The pipeline keeps the supplied RetinaNet fixed and learns a second-stage classifier that decides, per detection, whether a poisoning artifact caused it.

Problem

  • The supplied detector responds to injected artifacts: single-pixel hot chains, beaded lines, short dashes and comet-like streaks.
  • The metric (maCADD) compares the submission against a hidden clean model's output.
  • Fine-tuning changes the confidence and geometry of every detection, so even a model that unlearns the poison loses points on the genuine ones.

Approach

Reproduce the supplied detector's outputs, extract a 1,039-dimensional vector per detection from hooked FPN and class-tower activations plus 14 pixel-morphology measures and the confidence, and train a poison-versus-clean probe on the annotated unlearning images with dihedral augmentation, synthetic clean streaks and synthetic poison. Then keep, soften, drop or demote each detection by its poison probability.

Map

Decisions

Decision Alternative Why Trade-off
Triage detections with a second-stage probe Fine-tune the detector The detector's genuine outputs stay identical to the supplied model's Cannot remove artifacts the detector never boxed
Features from the frozen detector's own activations Train a separate image classifier The probe sees what the detector saw at each box Tied to this detector
Synthetic clean and poisoned streaks Annotated data only More training signal for a small labelled set Synthetic artifacts may not match real ones
Soften as well as drop Binary keep/drop Hedges uncertain cases under the metric One more threshold

Limits

  • No final score or placement is recorded in the repository.
  • Some later experiments depend on cached artifacts from code not in the repository; those are identified in the README.

Links

  • Repository: https://github.com/atharvgaur1845/NeuralDebrisRemovalinStreakDetectionModels

Narrative consistency with BDH

  • PROJECT
×
overviewproblemapproachmapdecisionslimitslinks

Overview

A pipeline that decides whether a proposed character backstory is consistent with a long novel. It pretrains a Baby Dragon Hatchling (BDH) language model on the novels, uses it for retrieval and classification, and includes probes that save per-layer attention maps.

Problem

  • The evidence for or against a backstory is scattered across a whole novel, far beyond one context window.
  • The classifier has to judge consistency, not just keyword overlap or name matches.

Approach

Novels are cut into 400-token windows with 100-token overlap, filtered to chunks mentioning the character, and scored by 0.6 × BM25 + 0.4 × dense similarity from the pretrained BDH model. The top three chunks join the character and backstory as one input. The BDH body is fine-tuned BitFit-style (layer norms and biases only) with a classifier head; negatives come from swapping character names inside true backstories.

Map

Decisions

Decision Alternative Why Trade-off
Hybrid retrieval, 0.6 BM25 + 0.4 dense One retriever Lexical matches and semantic similarity catch different evidence Two indexes
Drop the character's name tokens from retrieval keywords Keep them Retrieval keys on content, not on the name appearing Can miss name-specific facts
BitFit-style fine-tuning Full fine-tuning Few trainable parameters on a small labelled set Less capacity to adapt
Name-swap negatives, balanced Natural negatives only Forces the model to check facts against the character Synthetic negatives may be easier than real ones

Limits

  • No final score is recorded in the repository.
  • An experimental dendritic branch exists (active dendrites, dendritic norm, R-Drop, SWA) and is not the main pipeline.

Links

  • Repository: https://github.com/atharvgaur1845/BDH_based_system_for_long-form_narrative_consistency_evaluation
